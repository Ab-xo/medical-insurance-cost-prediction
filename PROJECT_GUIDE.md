## 3. Quick Start

| Tool    | Version                |
| ------- | ---------------------- |



```bash

python3 -m venv .venv
source .venv/bin/activate
```

```bash
cd frontend && npm install && cd ..
```

```powershell

```

```bash

```

```bash

```

### Start the dashboard

```bash
cd frontend && npm run dev
```

Open `http://localhost:3000` · API docs at `http://localhost:8000/docs`

## 4. Dataset

**Source:** [Kaggle — Medical Insurance Cost Dataset](https://www.kaggle.com/datasets/mosapabdelghany/medical-insurance-cost-dataset/data)

| Column     | Type  | Range          | Description                  |
| ---------- | ----- | -------------- | ---------------------------- |
| `age`      | int   | 18–64          | Age of primary beneficiary   |
| `sex`      | str   | male/female    | Biological sex               |
| `bmi`      | float | 15–53          | Body Mass Index (kg/m²)      |
| `children` | int   | 0–5            | Number of dependants         |
| `smoker`   | str   | yes/no         | Current smoker               |
| `region`   | str   | 4 values       | US residential region        |
| `charges`  | float | $1,122–$63,770 | **Target** — annual cost USD |

**Summary stats:**

- 1,338 rows, 0 missing values, 1 duplicate removed → **1,337 clean rows**
- Train split: **1,069** rows · Test split: **268** rows (80/20 stratified by smoker %)
- Target skewness: **1.52** (right-skewed) · 139 high-value outliers (genuine, kept)
- Smoker mean: **$32,050** · Non-smoker mean: **$8,434** (ratio: 3.8×)

## 5. ML Pipeline

```
insurance.csv
  │
  ├─ clean_dataframe()          remove dup, validate ranges, standardise strings
  ├─ engineer_features()        add 8 derived columns (14 → 22 total after OHE)
  ├─ split_data()               80/20 stratified by smoker × charge quartile
  │
  ├─ ColumnTransformer
  │   ├─ numeric  → SimpleImputer(median) + StandardScaler   (linear/SVR only)
  │   └─ categorical → SimpleImputer(mode) + OneHotEncoder(drop='first')
  │
  ├─ 10 × Pipeline.fit()        each model trains inside sklearn Pipeline
  ├─ evaluate_model()           RMSE, MAE, R², train time on held-out test set
  ├─ run_cross_validation()     5-fold CV R² and RMSE on train set
  ├─ select_best_model()        composite rank + CV R² tie-break
  │
  ├─ joblib.dump(best_model.pkl)
  ├─ generate_all_eda_figures()         → outputs/figures/eda/
  └─ generate_all_evaluation_figures()  → outputs/figures/evaluation/
```

Each model is a standalone `sklearn.Pipeline(preprocessor → estimator)`.
Preprocessing is baked into the pipeline, so `best_model.pkl` is self-contained —
no separate scaler or encoder files.

## 6. Feature Engineering

`src/feature_engineering.py` — adds 8 features on top of the 6 raw inputs.
**No target leakage** — all features use only input columns.

| Feature        | Type        | Logic                                                                                          | Motivation                                        |
| -------------- | ----------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `age_group`    | categorical | `<30` → young, `30–50` → middle_age, `>50` → senior                                            | Captures nonlinear age-cost curve                 |
| `bmi_category` | categorical | WHO thresholds: `<18.5` → underweight, `18.5–25` → normal, `25–30` → overweight, `≥30` → obese | Clinical risk buckets                             |
| `is_obese`     | binary      | 1 if BMI ≥ 30                                                                                  | Binary obese flag                                 |
| `smoker_obese` | binary      | 1 if smoker = yes AND BMI ≥ 30                                                                 | **Key interaction** — highest-charge group by far |
| `age_bmi`      | numeric     | age × bmi / 1000                                                                               | Compound metabolic-age risk                       |
| `has_children` | binary      | 1 if children > 0                                                                              | Family-size signal                                |
| `family_size`  | categorical | 0 → individual, 1–2 → small_family, 3+ → large_family                                          | Ordered family bucket                             |
| `age_smoker`   | numeric     | age × (1 if smoker else 0)                                                                     | Older smokers pay substantially more              |

These features are why linear models outperform tree ensembles — the charge
surface becomes approximately linear once the interactions are encoded.

## 7. Model Training & Selection

### Alpha tuning

**Before:** `Ridge(alpha=0.1)` and `Lasso(alpha=2.0)` — hardcoded, arbitrary.

**Now:** `RidgeCV` and `LassoCV` — alpha selected by cross-validation:

```python
RidgeCV(
    alphas=[0.01, 0.05, 0.1, 0.5, 1.0, 2.0, 5.0,
            10.0, 20.0, 50.0, 100.0, 200.0, 500.0, 1000.0],
    scoring="neg_root_mean_squared_error",
)

LassoCV(
    alphas=100,        # 100 candidates on the regularisation path
    cv=5,
    max_iter=50_000,
    random_state=42,
)
```

The chosen alpha is logged during training:

```
[1/9] Ridge Regression
  → CV-selected alpha = 0.5
[2/9] Lasso Regression
  → CV-selected alpha = 12.3
```

### Model selection composite score

```
composite = 0.45 × rmse_rank + 0.35 × mae_rank + 0.20 × r2_rank
```

Models with composite scores within 0.5 points of each other are considered
tied — the tie is broken by 5-fold CV R² to ensure generalisation wins over
lucky test-set performance.

### Scaled vs unscaled models

| Scaled (StandardScaler applied)      | Unscaled                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------- |
| Linear Regression, Ridge, Lasso, SVR | Decision Tree, Random Forest, Gradient Boosting, Extra Trees, XGBoost, AdaBoost |

|     8 | Gradient Boosting    |     $4,708 |     $2,467 |     0.8745 |     0.838 |      7.30 |
|     9 | AdaBoost             |     $5,448 |     $4,402 |     0.8319 |     0.790 |      9.00 |
|    10 | XGBoost              |     $4,659 |     $2,407 |     0.8771 |     0.844 |         — |

**Why Lasso wins over Ridge:** L1 regularisation shrinks irrelevant coefficients
to exactly zero — effective feature selection. With dominant features like
`smoker_obese` and `age_smoker`, Lasso prunes noise more aggressively than L2,
giving marginally better generalisation.

**Why linear models beat tree ensembles:** The 8 engineered features encode the
charge relationships as near-linear combinations. Once `smoker_obese`,
`age_smoker`, and `age_bmi` exist, a linear model can fit them directly without
needing tree splits.

## 13. Key Design Decisions

| Decision                                       | Reason                                                                                                                          |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **LassoCV / RidgeCV over fixed alpha**         | Alpha tuned by cross-validation — no guessing, reproducible across machines                                                     |
| **Lasso wins over Ridge**                      | L1 shrinks irrelevant coefficients to zero; better suited when a few features dominate                                          |
| **Interaction features over raw inputs**       | `smoker_obese` and `age_smoker` encode the two largest nonlinear effects as linear columns, letting Lasso exploit them directly |
| **Single `best_model.pkl` with full pipeline** | Preprocessing baked in — no version drift, no missing scaler files                                                              |
| **`<img>` not `<Image>` for backend plots**    | FastAPI serves dynamically-named PNGs; `next/image` requires statically-known paths at build time                               |
| **FastAPI + Next.js separation**               | Clear boundary: Python owns ML and data, TypeScript owns UI — no server-side Python in Next.js                                  |
| **Stratified split on `smoker`**               | Smokers are 20% of data; stratifying preserves this ratio in train and test sets                                                |
| **`outputs/` gitignored**                      | Plots and metrics are reproducible — regenerated by `python -m src.train`                                                       |
